# ExamGuard — Milestone 1 & Milestone 2

Smart Examination Monitoring Platform with Integrity Analysis & Reporting.
This delivery covers **Milestone 1 (Week 1–2)** and **Milestone 2 (Week 3–4)** only.

## What's implemented

### Milestone 1 — Candidate Authentication & Session Management
- **System architecture / DB schema** — `db.py`. SQLite schema covers candidates, exam
  sessions, face-absence events, activity events, flagged events, and placeholder tables
  for integrity scores / AI reports (reserved for Milestone 3+).
- **Flask app + candidate auth** — `auth.py`, `app.py`. Registration, login, salted
  password hashing (`werkzeug.security`), session-cookie based auth guard.
- **Photo capture at registration (OpenCV)** — browser `getUserMedia` + `<canvas>` capture
  (`templates/register.html`) posts a base64 JPEG to the server, which runs an OpenCV
  Haar Cascade face check (`auth.verify_face_present`) before persisting the candidate.
- **Session lifecycle management** — `session_manager.py`. Explicit state machine
  (`created → active → paused → active → submitted`) with illegal-transition rejection;
  every transition is also written to the `activity_events` log.
- **Synthetic session log generator (Week-1 warm-up)** — `data_generator.py`, built with
  Faker. Produces candidates + sessions across three behaviour archetypes (clean /
  distracted / high_risk) so later modules have a realistic corpus to work against.

### Milestone 2 — Face Presence, Event Logging & Detection Engine
- **Face presence monitoring** — `face_monitor.py`. Browser pushes webcam frames every
  3s (`static/js/monitor.js`) to `/api/session/<id>/frame`; server runs Haar Cascade
  detection and maintains an in-memory per-session absence tracker that opens/closes
  rows in `face_absence_events` with computed durations. No face recognition or
  liveness detection, per spec.
- **Browser activity & event logging** — `event_logger.py`. Captures focus loss/regain,
  tab-switch (`visibilitychange`), fullscreen exit, copy/paste, right-click, and a
  devtools-open heuristic; persisted to `activity_events` with timestamps. Rejects
  events for sessions that aren't `active`/`paused`.
- **Rule-based suspicious event detection engine** — `detection_engine.py`. Configurable
  `THRESHOLDS` dict drives six rules (tab-switch count, single/cumulative face-absence
  duration, focus-loss frequency, copy/paste volume, devtools). Results are (re)written
  to `flagged_events` and are idempotent per session.

## Project layout
```
examguard/
  app.py                 Flask app & routes (pages + JSON API)
  db.py                  SQLite schema + connection helpers
  auth.py                Registration / login + OpenCV photo verification
  session_manager.py     Exam session lifecycle state machine
  face_monitor.py        Haar Cascade face-presence tracking
  event_logger.py        Browser activity event ingestion
  detection_engine.py    Rule-based suspicious-event flagging
  data_generator.py      Faker-based synthetic session corpus generator
  validate_m1_m2.py       Automated validation script (run this first)
  templates/              Jinja2 pages (login, register, dashboard, exam room)
  static/js/monitor.js    Webcam capture + browser event listeners
  static/css/style.css    Styling
  requirements.txt
```

## Running it

```bash
pip install -r requirements.txt

# 1. Initialise the DB and run the full validation suite (M1 + M2 acceptance checks)
python validate_m1_m2.py

# 2. (optional) seed a synthetic corpus for manual exploration
python data_generator.py --candidates 25 --seed 42

# 3. Run the app
python app.py
# -> http://localhost:5000
```

A live run needs a webcam + browser (register → capture photo → start an exam →
the page streams frames and browser events in the background).

## Validation performed

`validate_m1_m2.py` is an automated check-suite (23 checks, all passing) covering:
- Registration success/failure paths (duplicate email, weak password), login success/failure.
- Haar Cascade correctly reports "no face" on a blank negative-control image.
- Full session lifecycle including rejection of illegal transitions (e.g. restarting a
  submitted session), and that every transition is logged.
- Face-absence interval open → close → duration correctness.
- Event logging correctness and rejection for non-active sessions / unknown event types.
- Detection engine: flags a session that crosses the tab-switch threshold, does **not**
  flag a session under threshold, and runs cleanly across a 25-session synthetic corpus
  generated by `data_generator.py` (only `high_risk`-archetype sessions get flagged,
  which is the expected behaviour given the default thresholds).

## Not in this delivery (later milestones)

Integrity scoring, Data Science analytics/clustering, the LangChain AI report agent,
alert/evidence screenshot storage, the Streamlit dashboard, and JSON/CSV export are
Milestone 3–5 scope per the project plan and are intentionally not included here
(though `db.py` reserves the `integrity_scores` and `ai_reports` tables for them).
